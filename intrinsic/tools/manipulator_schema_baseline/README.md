# Manipulator public schema baseline

Checked-in inventory of protobuf and FlatBuffer symbols that must stay
wire-compatible and source-compatible for the manipulator baseline (issue
[#47](https://github.com/IshmaelRogers/intrinsic-core/issues/47), parent work
package [#13](https://github.com/IshmaelRogers/intrinsic-core/issues/13)).

The inventory file is
[`manipulator_public_schema_inventory.json`](manipulator_public_schema_inventory.json).
The extractor is
[`extract_public_schema_inventory.py`](extract_public_schema_inventory.py).
It only reads existing `.proto` and `.fbs` sources. It does not edit schemas,
generate stubs, or change runtime behavior.

A senior API owner must approve this protected scope before the comparison
gate in #48 or the negative fixture in #49.

## Selection rule

Rule id: `manipulator-public-wire-v1`. The same text is stored on the inventory
as `selection_rule`.

A file is included only when it already exists in this repository and all of
the following hold:

1. It is a `.proto` or `.fbs` source. Generated stubs are not a second source
   of symbols.
2. It is not under `test`, `tests`, `testdata`, `testing`, or `fixtures`, and
   its name does not end in `_test.proto` or `_test.fbs`.
3. Its path is under one of these public manipulator surfaces, or it is one of
   the explicit files below.

Directory allowlist:

- `intrinsic_apis/intrinsic/motion_planning`
- `intrinsic_apis/intrinsic/icon` (ICON public API, including HAL config,
  action parameters, and fieldbus descriptions shipped in that package)
- `intrinsic_apis/intrinsic/kinematics`
- `intrinsic_apis/intrinsic/math`
- `intrinsic_apis/intrinsic/world/proto`
- `intrinsic_apis/intrinsic/geometry`
- `intrinsic_control/intrinsic/icon/actions` (joint and Cartesian action
  parameter protos, including ones that are not copied under `intrinsic_apis`)
- `intrinsic_control/intrinsic/icon/skills`
- `intrinsic_control/intrinsic/icon/hal/interfaces`
- `intrinsic_control/intrinsic/icon/flatbuffers` (shared types included by the
  HAL schemas)

Explicit files:

- `intrinsic_apis/intrinsic/skills/proto/motion_targets.proto`
- `intrinsic_apis/intrinsic/skills/proto/skill_parameter_metadata.proto`
- `intrinsic/world/proto/object_world_service.proto`
- `intrinsic/world/proto/object_world_updates.proto`
- `intrinsic/world/proto/robot_component.proto`
- `intrinsic/world/proto/generic_action.proto`
- `intrinsic/manipulation/skills/force/contact_stiffness.proto`
- `intrinsic_control/intrinsic/icon/control/primitives/force_control/proto/controller_params.proto`
- `intrinsic_control/intrinsic/icon/control/primitives/force_control/proto/force_primitives.proto`
- `intrinsic_motion_planning/intrinsic/motion_planning/proto/v1/motion_planner_service.proto`
- `intrinsic_motion_planning/intrinsic/motion_planning/proto/v1/motion_specification.proto`
- `intrinsic_motion_planning/intrinsic/motion_planning/skills/move_robot.proto`

`intrinsic_sdk` contains no `.proto` files. The SDK world and motion clients
use the ObjectWorld and MotionPlanner service protos listed above.

Imports and FlatBuffer includes that fall outside this set are listed in
`out_of_scope_imports` and are not expanded. No vehicle or UUV schemas are
introduced.

Not included, on purpose:

- `third_party` and Google well-known types
- ICON safety FlatBuffers under `intrinsic_control/intrinsic/icon/control/safety`
- IPC layout `segment_info.fbs`
- Vendor and fake hardware-module configs
- Internal planner configs (RRT, TOPP, path-planner options)
- `autogenerated_icon_config_service.proto`, realtime tracing, and the HAL
  introspection tool proto

## What each record contains

Each schema records:

- repo-relative path, `kind` (`protobuf` or `flatbuffer`), syntax
- protobuf `package` and FlatBuffer `namespace`
- imports or includes
- messages, tables, and structs (`layout`: `message`, `table`, or `struct`)
- fields with name, type, label, proto tag or FlatBuffer id (`number`),
  oneof, default, deprecated, and `required`
- reserved names and ranges, including `end: "max"`
- enums and numeric values (hex literals are stored as decimal integers)
- services and RPCs, including client and server streaming
- protobuf `extend` fields (custom-option tags)

FlatBuffer ids: tables use declaration order starting at 0 when the source
omits `(id: N)`. None of the current HAL schemas set an explicit id. Struct
fields use `id_kind: "positional"` because struct layout is ordered rather
than vtable-tagged. Reordering a struct field changes that index.

JSON object keys are sorted. Schemas are ordered by path. Fields are ordered
by number, then name. The writer does not embed timestamps or absolute paths.

## Commands

From the repository root:

```bash
python3 intrinsic/tools/manipulator_schema_baseline/extract_public_schema_inventory.py --self-check

python3 intrinsic/tools/manipulator_schema_baseline/extract_public_schema_inventory.py \
  --output /tmp/inventory_a.json
python3 intrinsic/tools/manipulator_schema_baseline/extract_public_schema_inventory.py \
  --output /tmp/inventory_b.json
cmp /tmp/inventory_a.json /tmp/inventory_b.json

python3 intrinsic/tools/manipulator_schema_baseline/extract_public_schema_inventory.py \
  --compare intrinsic/tools/manipulator_schema_baseline/manipulator_public_schema_inventory.json \
  /tmp/inventory_a.json
```

The generator also builds the inventory twice in memory and refuses to write
the file if those two serializations differ.

`--compare` loads two inventory JSON files:

- Identical inventories print `identical` and exit 0.
- Added schemas, messages, fields, enum values, or RPCs are reported as
  `additive:` and exit 0. `--strict` treats those additions as failures.
- A removed schema, message, field, enum value, or RPC exits 1.
- A renumbered proto tag or FlatBuffer id, a changed type, label, default,
  oneof, required bit, enum number, or RPC signature exits 1.

That compare mode is the local stand-in for the future gate. It is not wired
into CI here (#46 and #48 are separate). A removed or renumbered field in a
candidate inventory fails `--compare` with a field-specific
`incompatible:` line. `--self-check` covers that negative case in memory, so
this change does not add a broken production schema fixture.
